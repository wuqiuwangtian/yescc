# YesCC 0.1.0

发布说明草案；当前尚未发布，以下正式安装地址在批准发布后生效。

YesCC 包装真实工具链：正确代码原生编译/运行，C 错误按规则和受限模型候选尽力修复，自然语言或未知文本可以生成 C 或明确标注的创意兜底。源码不被覆盖，编译通过也不代表实现了原始意图。

与 alpha 相比，本版补齐跨平台/进程树/编码验证、模型费用预留与缓存/候选边界、唯一精确上下文补丁定位、多错误 C 组合修复、离线降级说明及结构化 CLI 错误。Python/JavaScript 保留原生直通，AI 修复与生成目标仅 C。

## 安装

发布后使用 `pipx install yescc==0.1.0` 或 `uv tool install yescc==0.1.0`。需要 Python ≥3.11；源码、运行依赖及许可分别保留在 wheel/sdist 中。

免安装候选资产：

| 平台 | 归档 |
| --- | --- |
| Linux x86_64 | `yescc-0.1.0-linux-x86_64.tar.gz` |
| Windows x86_64 | `yescc-0.1.0-windows-x86_64.zip` |

下载后与同批 `SHA256SUMS` 核对，再解压并保留整个目录，包括 `_internal`、`licenses` 和 `MANIFEST.json`。CLI 自带运行时；C 用户代码仍需 GCC，JavaScript 需 Node，Python 需 PATH 中的 Python 3。wheel 使用自身环境的解释器，冻结版使用实际找到的外部解释器，报告其真实版本。

Linux 在 Ubuntu 24.04 构建，记录 glibc 基线；不保证旧 Linux、musl/Alpine 或其他架构。Windows 以原生 CI 的验证范围为准；没有 macOS、MSVC 或跨文件项目构建支持。

## 三例

在解压目录执行，Windows 将 `./yescc` 换为 `.\yescc.exe`：

```bash
./yescc run examples/hello.c --offline
./yescc run examples/broken.c --offline
./yescc run examples/idea.txt --offline
./yescc examples/broken.c --explain --offline
```

前两例分别输出 `hello` 和 `repaired`。第三例在离线时明确标 `creative_fallback`，只回显原文本，没有实现自然语言意图。默认 stdout 保持用户程序输出，状态通过报告或 explain 查询。

## 脚本与隐私

- 构建/解释模式的 `--json` 返回正常 schema v1 报告或 `report_kind=command_error` 错误对象；后者读取 `error.exit_code`，不覆盖旧报告。`run` 的 stdout 属于用户程序，不接受 JSON 输出模式。
- `--strict` 关闭修复与兜底，`--no-fallback` 只禁止创意兜底；用法/不支持输入/构建/预算等退出码保持 100/101/102/103 分类。
- 原生成功不调用模型。配置并启用模型时会发送输入和编译诊断；`--offline` 禁止 YesCC 发模型请求，不控制原生程序网络行为。费用单位 USD，未知费用不能当作已知总价。
- AI 产物的运行隔离是尽力隔离，不能阻止所有文件系统访问或进程逃逸。具体平台限制见[使用与隐私指南](https://github.com/wuqiuwangtian/yescc/blob/main/docs/使用与隐私指南.md)。

候选测试区分自动回归、独立 AI 首跑和维护者验收；历史模型结果绑定其采样版本，没有为正式候选重新运行付费评测。完整证据与未测项见[评测入口](https://github.com/wuqiuwangtian/yescc/blob/main/docs/评测/README.md)。

YesCC 使用 MIT；捆绑组件分别适用原许可证，MIT 不替代它们。实际原文、来源及逐文件审计在候选的 `licenses/` 与 manifest 中。正式发布必须使用已复核的最终资产，不重新混入本机开发包或未覆盖的库。

问题请附版本、平台、命令、最小脱敏输入、原生对照和报告，提交到[问题入口](https://github.com/wuqiuwangtian/yescc/issues/new/choose)；不要上传真实密钥或私密源码。

## English summary

YesCC preserves native Python/C/JavaScript behavior and adds bounded C repair,
generation and explicitly labeled creative fallback. Every candidate is compiled;
compilation is not proof of semantic intent. Native archives bundle the CLI runtime,
while user programs still need their external toolchains. Isolation is best effort.
This document is a release draft, not a publication announcement.
