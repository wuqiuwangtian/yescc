# 使用、隐私与 Windows 安装

适用于当前源码；已发布 alpha 的能力与后续修补分开，版本状态见[路线图 §10](项目路线图与发布计划.md#10-待决事项与下一步)。能力矩阵与运行限制以 [README](../README.md) 为准。

## Windows 原生安装与验收

需要 Windows 原生 Python ≥3.11、uv、Git；C 构建另需 GCC，JavaScript 直通另需 Node.js。MSVC 不支持。WSL 的运行结果不算 Windows 原生验证。

可使用 MSYS2 的 UCRT64 GCC。安装和更新步骤以 [MSYS2 官方安装指南](https://www.msys2.org/)为准；UCRT64 的选择依据见[官方环境说明](https://www.msys2.org/docs/environments/)。在 **MSYS2 UCRT64** 终端安装：

```bash
pacman -S --needed mingw-w64-ucrt-x86_64-gcc
```

在 PowerShell 中临时配置工具链路径，再运行源码（路径按自己的安装位置调整）：

```powershell
$env:Path = "C:\msys64\ucrt64\bin;" + $env:Path
Get-Command python, uv, gcc
python --version
gcc --version
git clone https://github.com/wuqiuwangtian/yescc.git
Set-Location yescc
uv sync --extra dev --locked
uv run yescc --version
Set-Content -Encoding ascii hello.c '#include <stdio.h>
int main(void) { puts("hello"); return 0; }'
uv run yescc run hello.c --offline
uv run pytest tests/e2e/test_platform_boundaries.py -q
```

预期合法 C 原样构建运行；平台测试中的 POSIX 信号用例会跳过。`Get-Command gcc` 应指向预期工具链；若缺 DLL，保留同目录在 PATH。部分 MinGW 链接器对绝对 Unicode 输出路径会失败，可在项目目录使用相对 `-o output.exe`；YesCC 保留原生失败，不声称修好了工具链。UTF-8（含 BOM）与 CRLF 受支持，其他编码返回 101。

本指南命令未在维护者的实体 Windows 上手动走完；自动化原生 Windows 结果见评测记录。不要把 CI 的 PATH 配置推定为用户已经安装好工具链。

## 数据流与清理

| 场景 | 发送给模型的数据 | 本地留下的数据 |
| --- | --- | --- |
| 原生成功、`--strict` 或 `--offline` | 无 | 构建产物、报告；可能有原生诊断 |
| C 模型修复 | 当前源码、文件名、编译诊断、前次失败反馈 | 候选源码、实际 patch、原始 diff、调整记录、模型统计 |
| 自然语言/创意生成 | 输入文本、生成要求、前次构建反馈 | 生成源码、报告、候选缓存 |

云端端点首次提示上传；`--offline` 才是明确禁止模型请求的开关。自定义端点由你配置，服务端的数据保留政策需另行确认。回环地址被当作本地端点，这不证明它没有代理到云端。基准参考程序与预设答案不进入模型提示词。

`.yescc/<stem>/` 内的报告、源码、patch 和 `--trace` 日志可能包含敏感源码、文件路径和编译器回显；不要直接附到公开 issue。模型缓存位于平台用户缓存目录的 `yescc/model-v1`（可由 `YESCC_CACHE_DIR` 指定），保存模型响应。`--no-cache` 跳过缓存读写，不会清除旧缓存；停用命令后按需删除上述目录。文件没有加密，依赖操作系统权限，不能抵御同用户的其他进程。

API key 从环境读取，用作授权请求，不主动写入模型提示词；HTTP 错误回显中出现的当前 key 会先替换为 `[REDACTED]` 再截断。该处理不是任意秘密扫描器，不能保证移除你写在源码中的凭据。源码或模型响应中的秘密仍可能进入日志/缓存，提交前必须自行检查。

AI 运行仅尽力隔离：临时 cwd、环境白名单、超时、进程树清理；绝对路径和符号链接仍能访问宿主文件，输出没有产品级限流。需要处理不可信代码时，应另选容器或虚拟机环境。

## FAQ

**为什么编译成功仍不能称为修复正确？** GCC 检查语法和链接；程序可能算错、读取错误输入或改变原意。报告 `repaired/generated` 表示候选通过构建，需另用行为测试确认。

**为什么提示“生成成功”但退出不是 0？** 构建状态和运行结果分开。查看 `result.program_exit`、`limits` 和运行输出；超时为 124，用户取消为 130。创意兜底始终标为 `creative_fallback`。

**预算 0.05 是人民币吗？** 不是，是 USD。云端缺单价时不请求；`cost_known=false` 时 `cost_usd` 是已知小计。失败请求可能收费，预算是按配置价格估算，不能代替供应商账单。

**模型补丁行号不对怎么办？** 可按唯一精确旧文本块定位并重算行数；空白或正文不符、重复上下文、重叠和整文件改写仍拒绝。原始响应和调整说明进入报告，规则见 [ADR-0017](adr/0017-exact-context-patch-normalization.md)。

**Python/JS 错误也会修吗？** 当前 AI 目标只有 C；Python/JS 保留原生直通。需要原生失败原样返回时使用 `--strict`，避免进入创意兜底。


## RC 本地安装与反馈

当前 RC 尚未发布到 PyPI/TestPyPI；不要把 alpha 安装命令当成 RC 安装。先在已检出的开发分支运行 `uv build`，然后在新的虚拟环境用 `uv pip install --python <新环境的 python> dist/yescc-0.1.0rc1-py3-none-any.whl` 安装。只有维护者按锁文件约束执行的评测对应本仓库保存的依赖版本；普通安装允许的依赖范围见 pyproject。

维护者可复制运行 `uv run python -m bench.package_smoke --output dist/package-smoke.json`：脚本自动在仓库外创建新环境，按锁定的运行时依赖安装当前 wheel，检查三语言原生、C 规则/模型修复、自然语言生成、创意兜底、strict 失败、运行非零退出、凭据脱敏和原始许可文件。模型部分只使用本地假供应商；不代表真实模型质量。需要 uv、GCC、Node.js 及下载已锁定依赖的网络。

自用/受邀测试时，从 README 三例开始，再用自己的一份合法单文件程序和一份错误输入复核报告。反馈至少包含安装的版本/提交、OS/Python/GCC/Node 版本、最小可公开输入、完整命令、原生与 YesCC 的 stdout/stderr/退出码差异、报告状态；分享前移除源码与路径中的秘密。编译通过但行为错误需作为正确性失败报告，不能只附“成功”截图。

邀请测试的待验收条件是至少一名独立测试者完成上述路径并提供结果；自动化与协作助手自用不算独立用户验收。邀请动作、包上传及 Release 各自记录，当前任务状态以路线图 §10 为准。

可供测试者填写的最小反馈格式（维护者准备说明不等于已发出邀请）：

```text

自己的错误输入：预期行为、实际状态/产物/退出码：
核对报告（去除秘密后）：

```

人工抽查另记录固定样本 ID、输入规格、预期输出依据、候选实际行为和结论；编译结果不能替代意图判断。维护者把经过确认的反馈证据存入 `docs/评测/`，任务勾选只更新路线图。
