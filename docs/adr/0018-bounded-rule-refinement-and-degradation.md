# ADR-0018：有界组合修复与离线降级说明

- 状态：已实施（2026-11-09）；用户选择优先改善多错误 C 与离线提示。
- 补充 ADR-0014/0015；不扩大 C 语言范围，不改变 ADR-0009 的兜底状态和退出码。

## 原因

维护者实测 RC1 示例可用，但多错误输入很快进入仅回显输入的创意兜底。额外样本同时有缺少 include 的 `#`、智能引号、缺标点、括号不配对和 C++ `cout <<`。必须把机械语法错误与跨语言意图分开；不能用删除语句、猜变量或硬编码输出通过样例。

## 修复契约

- 原生成功与 strict 路径不变，不改源码、不加原生编译参数、不调用模型。
- C 规则组合增加缺少 include 的 `#`、语法树明确缺失的语句分号；组合已有标点、拼写、括号和引号规则。成对智能引号先归一化边界，再保护其内部文字；不替换字符串/注释内的中文标点和标识符。
- 初始候选来自最多 12 个静态组合及原生诊断的分号定位；语法树无错误只影响优先级，不是正确性结论。失败候选可依据当前 GCC 的分号建议或树中的缺失分号再细化；重复源码不重编译，整个规则阶段最多 **24 次候选构建**，每条候选路径最多 **4 次细化**。上限不包括已有的原生构建；没有新增候选时立即退出。
- 内部规则候选构建额外使用 `-fdiagnostics-parseable-fixits`，仅取得 GCC 建议。只接受当前源码文件的零宽分号插入，UTF-8 字节列严格转换；不采用替换/删除或其他文件的建议。格式依据 [GCC 官方诊断说明](https://gcc.gnu.org/onlinedocs/gcc/Diagnostic-Message-Formatting-Options.html)。无法解析的建议忽略。
- 对英文 GCC「expected … ; … before …」诊断，允许在前一个非控制头、非宏/续行、非注释的物理行末生成分号候选；不依赖显示列号。其他语言诊断不能据此保证同样覆盖率。自动分号不进入 for 头部，宏和续行采取保守跳过。
- 内部临时候选、落盘修复源码和 patch 禁止平台换行再转换，避免 Windows 将已存在的 CRLF 写成额外行；诊断必须对应实际编译文本。
- 每个候选交真实工具链验证；只返回完整构建成功的候选。不把“错误变少”当成修复成功，也不把未编译成功的中间文本直接写回或作为修复产物。
- 模型依旧接收原始输入和原始诊断；局部失败候选不隐式变成新的意图基线。模型候选、调用、费用、时间上限和缓存契约不变。

## 降级说明

- 不自动把 C++ 转 C、不切换到 g++。字符串/注释外的 `std::`、`cout <<`、`cin >>` 仅提供特征提示；不是完整语言识别。
- `creative_fallback` 和 `fallback.kind` 保持原语义。确定性兜底新增 schema v1 字段 `result.fallback.guidance: list[str]`，说明是否为输入回显、offline/模型配置/预算与尝试限制、规则尝试次数以及可用开关。字段基于实际执行路径。
- 普通输出将同一说明写 stderr，`--explain` 展示说明，`--json` 仍只输出一个 JSON。`print_input` 的程序输出保持不变；增加说明不冒充创意能力提高。
- 编译成功不证明意图等价。新增多错误测试的行为检查与原 M4 冻结数据分列；不修改其输入或 oracle。

## 验收数据迁移

原 M5 失败审计的预算样本是漏分号，新增规则会在模型预算检查前真实修好它。审计升级为 `m5-failure-v2`，仅将预算样本改成未声明符号，以继续检验预算阻断。保留旧原始证据和指纹，不把旧失败样本冒充仍失败。模型流程测试同理改用未知函数映射，确保真实进入模型路径。M4 的 200 例与 oracle/指纹不变。
