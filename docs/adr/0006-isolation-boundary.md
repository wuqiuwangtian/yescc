# ADR-0006：执行与隔离边界

- 状态：已接受（2026-11-03）；由 [ADR-0013](0013-sandbox-and-run-semantics.md) 修订
- 相关：[需求报告 §9](../初版需求报告.md)、[路线图 §6.10](../项目路线图与发布计划.md)

## 背景

修复与验证阶段可能构建并运行由模型生成的代码。它可能读写文件、启动子进程或访问网络。另一方面，用户显式 `yescc run` 时期望的是自己的真实环境语义。

## 决策

区分两类执行：

1. **验证执行**（系统发起）：在临时目录副本中执行；环境变量白名单；剔除 `FCOMP_*` 与常见密钥变量；超时；POSIX 上用 `setrlimit` 限制资源；Linux 上尽力用 `unshare -n` 断网，失败则报告 `network_isolated=false`；Windows 首版只做超时与进程树清理。
2. **用户显式运行**（`yescc run`）：在用户真实 cwd 执行，仅加超时，不做额外限制。

其他约定：

- 源文件永不覆盖；补丁与报告写入 `.yescc/`；
- 构建失败不留下看似属于本次成功的陈旧可执行文件；
- 取消/中断后清理临时目录，不再发起模型调用；
- **不宣称强隔离**：报告中的 `limits` 字段与实际能力一致，README 的「已知限制」逐平台列出。

## 后果

- 正面：安全边界可解释，用户能判断风险。
- 负面：Windows 上没有网络隔离，不能把「验证通过」解释为「任何环境下都安全」；文档必须明确。
