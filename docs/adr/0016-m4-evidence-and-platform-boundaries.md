# ADR-0016：M4 基准、对抗验收与跨平台边界

- 状态：已实施，跨平台 Gate 验证中（2026-11-04）；补充 ADR-0013/0015。
- 范围：完成既定 M4，不扩展语言、不增加强隔离承诺、不发布安装包。
- 状态来源：[路线图 §10](../项目路线图与发布计划.md#10-待决事项与下一步)。

## 基准与证据

- 固定 200 例及预先给定 oracle，比例仍为 50/50/30/40/30；原有 90 例合法回归保留。定义和比较方式见 [bench/README](../../bench/README.md)。
- 数据及被测源码均写入 SHA-256，区分冷/暖缓存和未执行项；假模型测试不冒充真实模型质量。真实评测只上传任务必要输入，预定 oracle 和参考实现不进入提示词。
- G4 的“行为符合声明”同时覆盖应阻断行为和明确不阻断的行为，例如使用绝对路径或符号链接访问测试目录。所有敏感数据均使用临时目录中的虚构内容，不读维护者真实密钥。
- 跨平台类型检查只是预检查；Windows Gate 必须有原生 Windows 运行记录。CI 在任务分支推送时也运行，保留各平台基准 artifact，便于不同 AI 核对。

## 运行与报告

- schema v1 新增 `limits.environment_filtered/process_tree_cleanup/resource_limits/filesystem_isolated/output_limited`，已有字段类型不变。
- 默认 AI 运行：环境过滤为 true；POSIX 清理模式为 `posix_group`，资源限额模式为 `posix_best_effort`；Windows 为 `windows_taskkill` / `none`。资源模式表示平台上的尽力设置，不能当成所有限额设置均成功的证明，对抗测试另检查实际子进程观察值。
- 仅构建和原生运行的环境过滤/清理/资源模式为 false/none；`--unsafe-run` 关闭环境过滤和资源限制，但保留超时与进程清理。
- 文件系统和输出流隔离始终为 false：临时 cwd 只改变相对路径，绝对路径/符号链接和创建子进程仍允许；大 stdout/stderr 可以透传。评测器自己的输出读取上限不算产品能力。
- POSIX 进程组无法约束主动脱离组的后代；Windows 仍未引入 Job Object，不保证父进程先退出或脱离任务树的后代被清理。Windows 控制台 `CTRL_BREAK` 映射为 `KeyboardInterrupt`，从而走清理、报告和退出码 130 路径。
- Windows 的阻塞等待会延后 Python 信号处理，AI 运行等待使用短轮询以便及时执行控制事件处理器。中文 cwd/源文件与绝对 Unicode 输出路径分别验收：已观察到部分 MinGW ld 对后者原生失败；使用相对输出验证可用路径，另对原生失败做一致性测试，不能把工具链限制隐藏为通过或跳过。
- 超时退出 124，取消退出 130；它们记录的是运行失败，不能把构建状态 repaired/generated 改写为意图已验证。预算无兜底仍按 ADR-0015 返回 103。

## 构建路径修补

- AI 临时构建把 `-I/-L` 等已支持的路径选项按原 cwd 解析，增加原源目录的 quote include 搜索路径，避免路径切换破坏用户头文件；原生路径仍不注入参数。
- `-E/-M/-MM/-fsyntax-only` 未产生文件时不把工作目录里的旧可执行文件记作新产物；失败构建也不返回旧产物。

## 首轮真实模型反馈

固定数据首轮发现严格 diff 被拒绝，以及创意程序自行要求 stdin 的问题。保留原始冷/暖结果；提示词版本改为 `m4-1`，要求逐字复制物理行/保留 C 字符串转义，创意程序空 stdin、无参数时自主输出并结束。数据、oracle 与补丁护栏保持不变，复测另存；首轮与复测合计仍受本轮 $0.50 上限约束。

## 验收与后续

对抗测试至少 20 条，Windows 路径/CRLF/BOM/中文/空格/stdin/非零退出/真实控制事件逐项验证。所有实际结果统一写评测记录，待 CI 和基准核对后再更新 G4，M5 的失败样本审计与发布候选不在本次范围。
