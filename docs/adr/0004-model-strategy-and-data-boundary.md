# ADR-0004：模型策略与数据边界

- 状态：已接受（2026-11-03）；供应商范围由 [ADR-0008](0008-model-provider-coverage.md) 扩展，模型策略由 [ADR-0012](0012-model-tiers-and-providers.md) 修订；模型供应商范围由 [ADR-0008](0008-model-provider-coverage.md) 修订
- 相关：[需求报告 §8](../初版需求报告.md)、[路线图 §6.9](../项目路线图与发布计划.md)

## 背景

修复与自然语言生成需要理解意图，这是规则难以覆盖的部分。模型选择直接影响效果、成本、隐私与安装门槛。

## 决策

- **默认云端 API，接口限定为 OpenAI 兼容的 `/chat/completions`**；本地模型（Ollama / LM Studio 等）作为同一接口的替换实现，不作为首版内置能力。
- 提供方与密钥由用户配置：`base_url` / `model` / `api_key` 环境变量；不内置任何厂商密钥或免费额度。
- 无密钥时**优雅降级**为「仅规则修复」并明确提示，不自动联网。
- 只上传任务必要上下文：单文件 + 诊断 + 用户意图；不默认上传整个仓库。
- 模型输出只作为候选补丁：必须是 unified diff，由本地严格应用，再交真实工具链验证；不允许整文件改写。
- 预算硬约束：最多 2 轮、单任务时间与 token 上限；触顶即停并置 `budget_exceeded`。
- 缓存仅本地、按内容寻址、不跨用户共享；`--offline` 可完全禁网。
- 密钥只从环境变量读取，不写入配置、报告、日志。

## 后果

- 正面：用户可自选供应商；隐私边界可解释；成本可控。
- 负面：首次使用需要配置 key；无 key 用户体验降级，需要在 README 首屏说明。
- 合规：不引入 GPL 组件；模型供应商的数据条款由用户自行确认。
