# ADR-0010：AI 目标语言与能力矩阵

- 状态：已接受（2026-11-04）；修订 [ADR-0001](0001-first-release-language-scope.md)
- 相关：[路线图 §2/§6](../项目路线图与发布计划.md)、[需求报告 §7](../初版需求报告.md)

## 背景

ADR-0001 让 v0.1 对三种语言都声明「原生、规则、模型、生成、运行」五类能力。实际评估后认为：原生直通是低成本的，AI 修复与生成的成本随语言数量近似线性增长；同时，自然语言生成 C 比生成 Python 更符合「编译器产出独立可执行文件」的产品直觉。

## 决策

v0.1.0 能力矩阵：

| 能力 | Python | C | JavaScript |
| --- | --- | --- | --- |
| 原生直通 | 是 | 是 | 是 |
| 规则修复 | 否（0.2） | 是 | 否（0.2） |
| 模型修复 | 否（0.2） | 是 | 否（0.2） |
| 自然语言生成 | 否（0.2） | 是 | 否（0.2） |
| 运行 | 是 | 是 | 是 |

- 自然语言与伪代码的默认目标语言是 C；`--lang python|javascript` 可覆盖，但 v0.1 的生成路径只保证 C。
- Python/JS 的 AI 能力列入 0.2，不在 v0.1 的发布声明中。
- 未覆盖语言返回退出码 101，并说明当前矩阵；不得假装支持。

## 后果

- 正面：评测与质量工作收敛到 C，发布更可信；三语言原生直通保留，长期目标不删。
- 负面：Python/JS 用户会觉得「只编译不修复」；README 必须明确矩阵。
- 扩展条件：新增语言 AI 能力必须同时提供样本、评测与真实编译验证，才更新矩阵。
