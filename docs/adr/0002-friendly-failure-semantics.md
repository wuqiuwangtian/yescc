# ADR-0002：「不报错」的产品语义

- 状态：已接受（2026-11-03）
- 相关：[需求报告 §2.2/§5](../初版需求报告.md)、[路线图 §1](../项目路线图与发布计划.md)

## 背景

原始要求是「不向用户抛出传统编译器式的错误和警告」。但任意文本不存在唯一意图，依赖也可能缺失，无法保证任意输入都得到正确程序。若把「不报错」理解为「必定成功」，就只能靠静默失败或伪造成功来满足。

## 决策

「不报错」定义为四件事，而不是「永不失败」：

1. 默认不把内部诊断和堆栈直接甩给用户；
2. 系统先在预算内尝试修复；
3. 无法完成时用简短、友好的状态说明结束；
4. 保留可查询报告与准确退出码。

配套规则：

- 失败不得返回 0；未成功生成产物不得报成功；
- 构建成功但未做独立验证时，状态为 `built_unverified`，不写成「已验证」；
- `--strict` 是用户主动选择的次级模式，显示原始诊断；
- 用户程序自身的 stderr 与非零退出码原样保留，不属于编译器诊断。

## 后果

- 正面：诚实边界清晰，脚本可依赖退出码。
- 负面：部分用户会觉得「还是会失败」；README 与错误文案必须解释这一取舍。
