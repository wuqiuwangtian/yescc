# ADR-0017：按唯一精确上下文定位模型补丁

- 状态：已接受并实施（2026-11-05，用户确认）。
- 补充 ADR-0015/0016；不改变候选预算、缓存失效和真实工具链验证要求。

## 原因与取舍

M5 保存的 8 个真实响应中，6 个因错误的 hunk 行号而被 M4 拒绝；这 6 个响应的旧文本块均在原文中唯一、逐字匹配。重新请求模型消耗费用，却无法可靠改善元数据。选择本地重算元数据，保留严格的正文匹配；未采用模糊匹配、空白归一化或模型代写整文件。

## 接受规则

- 所有 hunk 的上下文/删除行组成完整旧文本块，在未经修改的原始源码中必须只匹配一次。比较保留空格、注释、字符串转义和物理行；行终止符沿用既有 CRLF/LF 比较规则。
- 用该位置应用正文；行数从正文重算。多个 hunk 必须按原文顺序且不重叠；不能用已消费的区域排除第二个匹配来制造唯一性。
- 没有旧文本的纯插入不重新定位，要求有效原文地址、旧行数为 0、新行数与正文一致。
- 拒绝不匹配、歧义、重叠、倒序、非法前缀和没有改动的补丁。禁止删除全部原文；保留原有大改写阈值（超过 10 行的文件，增删行数超过 max(10, 60% 原文行数) 时拒绝）。这是启发式护栏，不能证明补丁符合意图。
- 候选仍需真实 GCC 构建；编译通过只表示可编译，不等于意图正确。原始源文件不写回。

## 报告与重放

schema v1 的模型 `result.repair` 增加 `raw_diff`（原始模型 diff）和 `patch_normalizations`（元数据调整说明）；已有 `patch` 文件仍保存本地实际源码差异。无调整时列表为空。缓存保存原始响应，缓存命中也重新执行同样的匹配与编译验证。

捕获数据仅含合成源码、诊断、原始响应和用量，不含请求凭据。离线重放必须交真实工具链和冻结行为 oracle；重放成绩不能称作新模型 pass@1 或供应商质量提升。更严格的歧义检查可能拒绝旧解析器按行号可应用的重复上下文补丁，这是有意选择。
