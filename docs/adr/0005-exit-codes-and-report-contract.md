# ADR-0005：退出码与报告契约

- 状态：已接受（2026-11-03）
- 相关：[路线图 §6.5/§6.6](../项目路线图与发布计划.md)

## 背景

fcomp 既要像 gcc 一样可被脚本调用，又要在 `run` 模式下反映用户程序的退出状态。两套语义混在一起会产生歧义。

## 决策

fcomp 自身使用 100–104 保留退出码：

| 码 | 含义 |
| --- | --- |
| 0 | 成功 |
| 100 | 用法错误 |
| 101 | 不支持的语言/输入 |
| 102 | 构建失败或无法修复 |
| 103 | 预算/超时/取消 |
| 104 | 内部错误 |

- 在 `run` 模式下，若用户程序成功启动，退出码 = 用户程序退出码；fcomp 自身的失败使用上述保留码。
- `--json` 在构建模式下输出结构化结果到 stdout；`run` 模式下程序拥有 stdout，`--json` 按用法错误拒绝，报告始终落盘；人类摘要走 stderr，用户程序的 stdout/stderr 原样保留。
- 每次尝试写 `.fcomp/<stem>/report.json`，schema v1 只增不改；破坏性变更升 `schema_version`。
- 报告必须包含：输入摘要、语言与工具链、诊断、补丁、假设、构建状态、验证范围、耗时、token/费用、隐私字段。

## 后果

- 正面：脚本可区分「编译失败」「超预算」「用法错误」与用户程序返回码。
- 负面：用户程序返回 100–104 时与 fcomp 保留码重叠；通过 `--json` 报告与 stderr 说明消歧，文档中明示。
