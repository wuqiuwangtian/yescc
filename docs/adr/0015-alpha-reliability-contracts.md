# ADR-0015：Alpha 可靠性修补契约

- 状态：已实施（2026-11-04，本轮现有问题修复）；补充 ADR-0004/0005/0012/0013，不扩大首版范围。
- 依据：alpha 审查复现了无效缓存循环、事后费用检查、L2 不升级、原生输出丢失与超时残留子进程。
- 当前实施和验证状态：[路线图 §10](../项目路线图与发布计划.md#10-待决事项与下一步)。

## 决策

### 模型尝试、路由与缓存

- `--max-rounds` 是单任务模型候选尝试上限，默认 2；缓存命中也计一次。另限制实际请求次数，失败请求同样计数；缓存路径也检查墙钟时间。
- 近正确 C 首次选 L2；补丁为空、应用失败、请求失败或真实编译失败后，有 L3 就升级，仍共享任务上限。显式 `--model` / `--provider` 时跳过自动 L2；已知供应商别名使用对应默认端点，自定义端点继续用环境变量配置。
- 无效补丁、空源码与真实编译失败的候选清除缓存；键补入工具链信息。模型重试反馈统一随机临时目录，原始诊断仍保留在报告里。缓存不是正确性证据，命中后仍需验证。

### 费用与时间

- CLI `--budget` 一直使用 USD，默认 `$0.05`；这是工具默认值，不是维护者真实评测的开支授权。路线图 A3 的人民币评测约束仍有效。
- 价格使用 `YESCC_MODEL_L{2,3}_{INPUT,OUTPUT}_PRICE_PER_MTOK`，单位 USD/Mtok；允许明确配置 0，不允许负值、NaN 或无穷大。云端缺任一单价时阻止请求；回环本地端点可不配置价格，但费用标为未知，不能声称受到金额限制。
- 请求前以消息 UTF-8 字节数加 1024 的协议余量保守估算输入 token，按剩余费用压低输出 token 上限（最多 1024），再预留费用。不足以支付输入或一个输出 token 时停止。
- 请求失败或供应商缺少有效 usage 时不返还预留，并标记费用未知；有可靠 usage 则按配置单价结算。若供应商报告费用超过上限，保留真实记录、拒绝候选并停止进一步收费请求；不能撤回已产生的账单。
- 预算阻断且 `--no-fallback` 时状态为 `failed`、退出码 103；默认仍可进入零模型调用的确定性兜底并明确标注，不能因此丢失预算阻断原因。
- 每次尝试检查剩余墙钟时间，请求的 HTTP 超时不超过剩余时间，返回后再次检查。HTTP 客户端的分阶段超时不是操作系统级的硬截止，也不覆盖原生编译器无限运行；更强的任务级截止仍属于后续加固。
- 费用预留依赖用户正确配置单价和服务遵守输出限制；不保证供应商隐藏计费或错误账单。此边界必须随评测报告公开。

### 原生输出与运行清理

- 成功原生构建完整转发 stdout/stderr；`--strict` 失败也完整转发，不能用报告里截断的内容代替输出。JSON 模式仅输出报告，编译输出保存在 `attempts`。
- AI 产物在 POSIX 独立进程组运行，在超时、键盘中断和正常父进程退出时清理整个组；`--unsafe-run` 也保留超时和清理，只解除 cwd/环境/资源隔离。
- Windows 建立独立进程组，超时/中断时使用 `taskkill /PID ... /T /F` 尽力清理。尚未引入 Job Object，父进程提前退出、脱离进程组或任务树的后代不保证清理；不宣称强隔离。

临时候选构建复制产物时保护原输入及其符号/硬链接别名。显式`-o`指向输入及其链接别名在模型请求前预检并拒绝；默认产物同名则改存`.yescc/<源stem>/`，备选仍冲突也拒绝。该保护不改变正常原生成功的透传参数，不得靠覆盖源码保存AI产物。

### 报告 v1 的增量字段与准确性

- `model.calls` 包含发起后失败的请求；`model.cost_known=false` 表示不能从 `cost_usd` 得到总费用。为保持 v1 数字类型，`cost_usd` 保留为已知部分的费用小计；摘要与评测工具将未知费用明确显示为“未知”。
- `budget{limit_usd,committed_usd,attempts,blocked_reason}`：金额、含未结算预留的占用量、候选尝试数、流水线捕获的预算阻断原因。预留不是实际账单，不与已知费用相加当作支出。
- `privacy.cloud_used` 按是否尝试非回环端点请求判断；`uploaded_bytes` 是这些请求中消息 content 的 UTF-8 字节总数，不含 JSON/HTTP 开销，不保证服务已收到。回环地址的网关后端是否上云无法自动判断。
- `limits.sandboxed=true` 仅表示此次实际在默认隔离路径执行；仅构建、原生执行、`--unsafe-run` 都为 false。临时 cwd 不是文件系统访问控制，绝对路径仍可访问宿主文件。

## 验证与后续

使用本地假模型、真实 gcc 与受控子进程测试以上契约；具体结果只维护在评测记录。Windows 实测、全量对抗用例与 200 例模型评测仍按 M4 推进，本轮不得替它们勾选完成。
