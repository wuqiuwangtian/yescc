# ADR-0023 单次创意编译与按需解释

状态：已实施于开发分支。修订 ADR-0009、0018、0021 中关于成功兜底时必须打印失败说明的规定。0.1.0 已发布行为见原记录。

普通命令先走原生，再做有界机械修复。两层成功时直接交付产物，模型调用数为零。对无法识别的文本直接尝试解释。一次输入产生一份作品，解释报告读取本地文件；后续运行作品不建立模型对话。

- 实验选项 `--creativity default|wild` 控制模型可以偏离字面要求的尺度。默认保留数量和表达的目标，矛盾处允许提出假设。wild 允许改写结局。二者都是提示策略，不是随机采样温度。
- 默认坏 C 的同一请求可交精确补丁或完整解释程序。补丁仍按 ADR-0017 定位；完整作品进入创意候选的真实构建和输出检查。无法使用的补丁将剩余机会留给生成。wild 在规则未修好后直接尝试作品。候选、缓存命中、请求、预算上限继续共享。模型解释和补丁在报告中分别标记，不把改编说成修复。`--no-fallback` 仍只接受修复；显式可选 UBSan 检查继续沿原路径执行，创意请求前先做能力探针。
- 已发布的 `--play` 保留旧的强制路由供兼容。普通使用无需该开关。报告新增 invocation.creativity，旧报告不回填。
- 产出结果后默认 run 只转发作品输出。原生失败、诊断、回显原因、模型用量和解释假设留在报告与 `--explain`，`--trace` 可看过程。仍显示首次云端数据流提醒。命令错误、真实环境错误、显式严格模式以及用户程序的退出状态和诊断如实返回。
