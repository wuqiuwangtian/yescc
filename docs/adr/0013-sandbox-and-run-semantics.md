# ADR-0013：沙箱与运行语义

- 状态：已接受（2026-11-04）；修订 [ADR-0006](0006-isolation-boundary.md)
- 相关：[路线图 §6.9](../项目路线图与发布计划.md)、[需求报告 §9](../初版需求报告.md)

## 背景

ADR-0006 把用户显式 `run` 放在真实 cwd，以保证原生语义；但引入 AI 修复与创意兜底后，运行模型生成的代码需要更明确的边界。两者可以按「代码是否被本工具改过」区分。

## 决策

- **原生未修改代码**的 `run`：在用户真实 cwd 执行，只加超时，保持原生语义。
- **AI 修复/生成/兜底产物**的 `run`：默认在临时目录副本、环境变量白名单、超时、POSIX 资源限额下执行；Linux 尝试断网，Windows 仅超时与进程树清理并如实文档化；`--unsafe-run` 可显式覆盖。
- **验证执行**（系统发起的编译/测试）始终使用隔离目录，与用户显式运行区分。
- 源文件永不覆盖；产物、补丁、报告写入 `.yescc/`。
- 报告中的 `limits` 必须与实际能力一致；不宣称强隔离。

## 后果

- 正面：原生行为保真；AI 代码默认有边界；用户可显式选择风险。
- 负面：Windows 隔离能力有限，必须文档化；两种运行语义需要在帮助与报告中说明。
