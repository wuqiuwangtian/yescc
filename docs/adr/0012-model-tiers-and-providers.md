# ADR-0012：模型分级与供应商

- 状态：已接受（2026-11-04）；修订 [ADR-0004](0004-model-strategy-and-data-boundary.md) 与 [ADR-0008](0008-model-provider-coverage.md)
- 相关：[路线图 §6.8](../项目路线图与发布计划.md)、[需求报告 §8](../初版需求报告.md)

## 背景

ADR-0004 采用「云端优先」，ADR-0008 又扩展为四家原生协议。实际产品需要按难度选择模型：近正确代码用便宜/本地模型即可，复杂生成才需要强模型；同时为多家供应商各写原生协议会显著增加维护成本。

## 决策

- **两级模型路由**：
  - L2：Ollama / LM Studio / 小模型（本地优先），负责近正确补丁、错误分类、定位。
  - L3：DeepSeek / OpenAI / 其他强模型，负责复杂修复与自然语言生成。
- 路由依据：输入类型（源码/自然语言）、诊断类别、剩余预算；用户可用 `--model` / `--provider` 覆盖。
- **协议**：统一 OpenAI 兼容；Anthropic / Gemini / Azure 通过各自兼容端点或可选 LiteLLM 网关接入，不各写原生协议。LiteLLM 是可选外部网关，不作为硬依赖。
- 无可用 provider 时：L0/L1 照常，L2/L3 跳过，L4 走确定性兜底。
- ADR-0004 的数据边界与预算规则继续有效：只上传必要上下文、模型输出必须验证、最多 2 轮、密钥只从环境变量读取、缓存不跨用户。

## 后果

- 正面：成本与延迟可控；供应商接入成本低；本地模型可离线承担一部分工作。
- 负面：分级路由需要评测调参；兼容端点的行为差异需要文档化。
- 边界：不承诺所有供应商同等质量；能力矩阵逐项标注。
