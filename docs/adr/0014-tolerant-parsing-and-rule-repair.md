# ADR-0014：容错解析与规则修复

- 状态：已接受（2026-11-04）
- 相关：[路线图 §5 M2](../项目路线图与发布计划.md)

## 背景

L1 规则修复需要知道「错误发生在哪、是否在字符串/注释里」。纯正则无法可靠区分代码与文本，而完整解析器在语法错误时通常直接失败。Tree-sitter 能在存在错误时构造带 `ERROR` 节点的语法树，适合定位与局部修复。

## 决策

- 引入 `tree-sitter` + `tree-sitter-c`（Python 包，cp311–cp314 的 Win/Linux wheel 已确认存在）。
- v0.1 只对 C 使用 Tree-sitter；Python/JS 暂不接 AI 修复，保持原生直通。
- 用途：错误节点定位、判断改动是否落在字符串/注释、为规则修复提供局部范围；**不**用语法树直接生成补丁。
- 规则修复仍以「候选 + 真实 gcc 验证」为准；多候选按改动范围排序，不宣称意图正确。
- 不得全局替换中文标点；字符串与注释中的内容必须保留。

## 后果

- 正面：规则修复更准，误改风险下降；为后续结构化修复打基础。
- 负面：新增原生依赖与版本维护成本；Tree-sitter 的错误恢复不保证语义正确，仍需编译验证。
- 备选：若 Tree-sitter 集成成本超预期，退回「编译器 JSON 诊断 + 词法护栏」，但需记录偏差。
