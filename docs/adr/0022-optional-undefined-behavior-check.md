# ADR-0022：可选的创意运行期未定义行为检查

- 状态：已实施（2026-11-14）；用户确认显式可选、默认关闭，优先保持普通用户无感体验。
- 补充 ADR-0015/0019/0021；只扩展 `model_creative` 的显式 `run`，不修改默认提示、首版语言范围或发布授权。
- 依据：[2026-11-13 第四阶段研究](../评测/2026-11-13.md#第四阶段运行期未定义行为离线诊断)在 8 个工具链/模式配置中实际可用 7 个，Windows GCC runtime 缺库而 trap 可用；可用性须由用户实际工具链探针决定，不能从研究矩阵外推。

## 决策

### 开关与适用范围

- 提供布尔 CLI 开关 `--check-undefined`，默认关闭；不提供可自动开启它的环境变量。关闭时不执行能力探针、不注入编译参数，保留原缓存身份和运行语义。
- 仅当流程真正进入有剩余候选额度的 `model_creative` `run` 时适用。原生成功、规则修复、模型补丁修复、普通自然语言生成、内置梗和离线回显均不应用、不探针；开启开关但未进入该路径时，报告原因是 `not_model_creative`。先修复后进入创意时不追溯检查修复候选，也不增加或预留候选。
- `build` 带此开关立即以 `UsageError` / 100 拒绝，不执行能力探针或程序。有效 `--json` 继续按 ADR-0019 输出单一 `command_error` 对象，不生成构建报告或覆盖已有报告。`run --json` 的既有拒绝规则不变。
- 适用创意路径开始之前，拒绝与检查冲突的 sanitizer 配置、非可执行构建模式、response file、额外编译输出参数及无法验证的工具链转发/驱动配置（如 `-Wl,`、`-Xlinker`、`-B`、specs/plugin），错误为 `UsageError` / 100；不猜测或静默移除用户参数。其他路径不因这些仅属于可选检查的参数限制而失败。源文件保护是独立契约：显式 `-o` 指向原输入或其链接别名时，在模型请求前拒绝，不能先产生费用再仅返回无费用字段的命令错误。

### 实际工具链与能力探针

- 使用本次 `CAdapter` 实际选定的编译器及原用户参数，优先探测 runtime：`-fsanitize=undefined -fno-sanitize-recover=undefined`；不可用再探测 trap：`-fsanitize=undefined -fsanitize-undefined-trap-on-error`。不另找 Clang、不静默替换编译器，不注入或修改用户的标准、优化、宏等语义参数。
- 能力探针使用受控的定义良好与已知未定义行为程序，实际验证编译、链接、运行和预期控制结果。编译器接受参数不等于检查可用；runtime 还须验证运行库与诊断，trap 验证已知坏控制的异常退出。探针结果不能认证候选的诊断来源。
- 整个探针阶段使用 20 秒工作预算，单次编译最多 20 秒、单次控制程序运行最多 3 秒、stdout+stderr 合计最多 64KiB；单次操作还受整个探针阶段剩余时间限制；启动和清理可能额外耗时，不是操作系统级硬截止。继续沿用既有尽力隔离与进程清理，不把探针说成作品已经验证。
- 两种配置均不可用时，在该创意模型请求之前以正常构建报告 `failed` / 102 明确说明检查不可用，不新增模型请求，也不暗中改走回显。此前修复阶段可能已有模型请求，费用与上传记录保留实际值；不能统一填零。

### 候选构建、运行与失败

- 选择可用配置后，每个创意候选只编译一次，所得即带检查的产物；只实际运行一次，既作已有输出验证，也作本次可选检查。报告 `artifact` 指向该产物，runtime 产物可能依赖目标机器的 sanitizer 运行库，不额外生成或执行普通版本作对照。
- 候选编译最多 20 秒，并受模型会话剩余时间限制；候选运行沿用创意 `run` 的实际超时、64KiB 合计输出额度、空 stdin、环境与隔离路径。探针限制与候选限制分别记录。`--unsafe-run` 只保留既有放宽运行环境的含义，不解除检查、超时、输出额度或进程清理。
- 仍应用 ADR-0021 的有限源码与输出检查；编译失败、运行非零、超时、超量或其他已有验证失败，均按真实阶段记失败、失效缓存，并在原有候选、请求、费用和时间额度内重试。默认两候选不增加；耗尽后仍明确标注原确定性兜底，不把它当成通过可选检查的模型作品。取消/130 沿用直接结束规则。
- 只有成功作品的 stdout 按原字节转发；不打印探针或失败候选内容，不额外执行成功程序。候选实际 stderr 的有限摘录可进入报告和失败反馈；这不是可信的 sanitizer 签名。

### 报告 v1 与缓存身份

- schema v1 只增字段。开启开关时根对象增加 `undefined_behavior_check`，包含 `requested: true`、`scope: "model_creative"`、`available`、`mode`、`flags`、`performed`、`reason` 和 `probes`。未探针的能力记未知，不把未适用说成不可用；`performed` 仅在候选实际执行后为 true，探针执行本身不使其为 true。
- `probes` 如实记录能力尝试和限制；最终选择的 `mode` 为 runtime 或 trap，未选择时不填造模式或参数。`reason` 区分不适用、检查不可用与实际执行状态，不能从开关开启推断检查已做。
- 适用候选的 attempt 及最终 generated 检查结果记录 `mode`、`flags`、`performed`、`diagnostic_observed`、stderr 有限摘录及 `ub_detected: null`。编译失败时 `performed: false`；不填造执行结果。现有 `validation` 和 `validation_limits` 继续反映真实运行与限制，非零退出不改写成经认证的 UB。
- 候选能伪造诊断文本，trap 的非零退出也可能另有原因，因此 `diagnostic_observed` 只表示观察到诊断形状，不能据此将 `ub_detected` 置 true。通过检查也不将它置 false。
- 只有开启检查的创意缓存身份增加稳定 validation profile 版本、所选 mode/flags 与实际编译参数。探针随机目录、时间与耗时不进入缓存身份；关闭开关时原 key 保持不变。命中仍消耗候选并重新构建/运行，坏编译和坏运行仍失效，不靠旧缓存跳过检查。
- 不修改 `PROMPT_VERSION`。模型调用、费用预留与已知费用、缓存次数、privacy 上传字节和最终实际隔离状态继续遵守 ADR-0015/0021；probe 不伪装成模型请求，也不以探针隔离状态覆盖最终产物的限制记录。

## 边界与验证

UBSan 只检查本次执行路径中的一部分错误，不是语义裁判、安全沙箱、意图正确或无 UB 保证。研究已观察到固定 O0 下堆越界与释放后读取沉默；未执行的坏分支、内容矛盾和作品趣味也不由它判断。插桩可能改变产物及运行库依赖，不能用普通编译/运行的结果代替本次实际行为。

生产实现使用独立模块，不导入 `bench.ubsan_study` 研究代码。回归只用本地假模型与真实工具链，不调用付费 API、不读取真实密钥；覆盖默认零额外行为、各非适用路径、参数拒绝、能力不可用零新请求、runtime/trap 选择、单次构建/运行、缓存隔离、失败重试和报告事实边界。平台支持及实际验证证据保存在 `docs/评测/`，当前实施与后续事项只维护路线图 §10，不将研究 7 个可用配置视为生产跨平台验收完成。
