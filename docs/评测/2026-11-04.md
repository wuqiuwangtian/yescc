# 2026-11-04 基线：M2 规则修复与确定性兜底

## 环境

- WSL2 / Arch Linux，x86_64
- Python 3.11.15（uv 虚拟环境）
- gcc 16.2.1
- tree-sitter 0.26.0 / tree-sitter-c 0.24.2

## 方法

- 受控损坏样本：`tests/fixtures/broken_c_cases.py`，53 例，覆盖全角标点（括号/分号/逗号/运算符/引号）、缺失右花括号、缺失右圆括号、缺失引号、常见拼写、组合错误。
- 判定：`yescc run` 后退出码 0、stdout 与预期一致、源码 sha256 未变、报告状态为 `repaired`、修复规则非空。
- 合法回归：M1 的 90 例三语言样本继续通过（原生直通、0 模型调用）。
- 兜底：不可修复源码与未识别文本默认 `creative_fallback`；`--strict` / `--no-fallback` 可关闭；缺头文件等环境/依赖问题标记 `failed`。
- 包装开销：`bench/overhead.py --repeat 10`。

## 结果

| 指标 | 结果 |
| --- | --- |
| 受控损坏样本修复 | 53 / 53（100%） |
| 合法样本回归 | 90 / 90，源码 0 修改、0 模型调用 |
| 单元 + e2e 测试 | 244 passed |
| 兜底状态 | 未识别文本与不可修复源码为 `creative_fallback`；缺依赖为 `failed` |
| 包装开销 P95 | Python 44 ms / C 44 ms / JS 49 ms |

## 限制

- 规则只覆盖确定性错误；复杂语义错误、缺失分号等仍会进入兜底（M3 由模型处理）。
- 缺失括号的插入位置是启发式，可能通过编译但语义与原意不同；测试只覆盖可判定的样本。
- Tree-sitter 的错误恢复不保证语义正确，最终仍以真实 gcc 编译为准。
- 兜底程序当前只打印原始输入；模型创意解释在 M3。
- 包装开销只测小文件冷启动，未测大文件或并发。

## 同日补充：M3 真实模型小样本

### 环境与模型

- DeepSeek（`deepseek-chat`），OpenAI 兼容端点；单价按配置的 $0.27 / $1.10 per Mtok 估算。
- L3 单级配置（L2 未单独配置）；单任务预算 $0.05、最多 2 轮。

### 结果

12 例小样本（4 个规则无法修复的 C 错误 + 8 个确定性自然语言任务）：**12/12 通过**。

- 修复：4/4，状态 `repaired`，1 次调用/例。
- 自然语言：8/8，状态 `generated`，1 次调用/例；1 例命中缓存。
- 延迟：修复 1.2–1.8 s；生成 1.0–2.1 s。
- 首次完整运行费用 $0.002568、4016 tokens；缓存后重跑 $0.001232。
- 整活输入单独 10 例：10/10 产出可运行程序；已知梗走本地规则 0 调用，其余 4 例模型创意解释，费用 $0.003484。

### 限制

- 样本量小（12 + 10），不等于路线图 M4/M5 的 200 例结果。
- 只测了 DeepSeek 一个供应商；不同模型的质量与费用差异未测。
- 通过标准是 stdout 与预期一致；自然语言任务的意图正确性仍依赖用例覆盖。
- 费用为按配置单价估算，不是账单截图。

- 基线 `be5d017`，任务分支 `fix/alpha-reliability`，本轮为未发布的本地修复；提交标识以 `git log -1 --oneline` 查询，不把同版本号的 TestPyPI 包当作本轮产物。
- Linux x86_64 / WSL，Python 3.11.15，gcc 16.2.1，tree-sitter 0.26.0。
- 所有模型验证均使用本地假服务器或模拟响应；回归夹具清除继承的 `YESCC_MODEL_*` / `FCOMP_MODEL_*`，隔离用户缓存，不读取真实密钥、不调用付费模型。

### 修复与回归证据

| 原问题 | 现在的行为 | 回归入口 |
| --- | --- | --- |
| 无效补丁命中缓存后循环 | 含缓存的候选尝试有限；无效候选失效；缓存路径检查截止时间 | `tests/test_model_session.py` |
| 单次调用突破预算、费用未知当零 | 请求前预留、压低输出 token；失败计数并保留预留；缺云端单价阻止请求；缺 usage 标注未知；供应商超额费用保留记录但拒绝候选 | `tests/test_model_session.py`、`tests/e2e/test_model_flow.py` |
| L2 不升级、显式模型覆盖无效 | L2 空/无效补丁、请求或编译失败后升级 L3；显式覆盖优先 | 同上；包含真实 gcc 编译失败的升级回归 |
| 原生 stdout 丢失、strict 诊断截断 | `-E/-M/-Wall` 与 gcc 对照输出一致；strict 失败输出超过 4000 字符仍完整；JSON 输出不混入预处理文本 | `tests/e2e/test_native_passthrough.py` |
| 超时后残留子进程 | 默认及 unsafe 路径都清理；POSIX 中断与父进程正常退出后清理进程组 | `tests/e2e/test_sandbox.py`；Windows 实际执行未验证 |
| 报告误标云端/隔离/费用 | 本地请求不算云端，远程请求记录消息内容字节；仅构建不算沙箱运行；费用未知明确显示 | `tests/test_model_session.py`、`tests/test_report.py`、`tests/e2e/test_model_flow.py` |
| 重试成功缓存无法复用 | 给模型的编译反馈统一随机临时目录；原始报告诊断不变；重跑时失败 L2 候选不复用、成功 L3 候选命中缓存 | `test_l2_compile_failure_upgrades_to_l3` |
