### 能跑但不完整或缺乏创意

- **非法UTF-8，F10“赛博土豆”**：把二进制数组算出的178用`%c`输出为单字节`0xB2`，stdout不能按UTF-8解码。源码、原始字节及哈希已保留，不能把宿主显示的`�`误当字体缺字。两位都把完整性评为1。
- **正文缺行，F18“三个笑脸”**：先`puts`确定stdout为窄流，随后`wprintf`的三条表情名称没有输出。实际只剩标题和结尾，退出仍为0、字节仍是合法UTF-8。说明“非空+合法编码”也不能保证作品完整。
- **模板化**：不少作品把输入翻译成英文，随后统计字节/字符或加通用状态行。S14锅里会议的默认作品基本是“土豆要求加薪、胡萝卜反对加班、盐宣布休会”的提纲改写，两位对其是否达到strong存在分歧，创意维度都只有1。
- **重复不稳定**：5输入各3次，15个模型作品都能运行；追加10次中两位分别认可4个、5个strong。显卡同题另一次只输出“retirement request acknowledged / render with kindness”，明显不及前述退休剧场。没有按最好一次汇报。

## 3. 失败根因与实际入口

### 3.1 三次失败主要是链接，不是想不出作品

F02“奇变偶不变”、F22“纸飞机与宇宙”、F28“风扇摇篮曲”各两份模型候选，都用了`sin/cos/floor`等数学函数。产品GCC命令没有`-lm`，模型收到失败诊断后仍继续使用它们，最终退回原文打印。

独立agent提取6份真实候选，保持源码字节不变，用同一GCC分别不带/带`-lm`编译：**6/6前者链接失败，6/6后者编译并运行成功**，分别输出三角函数表、纸飞机轨迹和风扇波形。该实验不追认默认产品成功，也不等于六份作品创意都好。源码审查由AI完成，原字段`manual_source_review`不能理解成人工验收。

### 3.2 配置名和默认思考不是透明替换

原配置别名探测成功，实际响应为deepseek-flash；直接请求deepseek-flash的同类输入则`finish_reason=length`，1024个输出token全部为reasoning，content为空，产品只报告“模型输出中没有JSON对象”并打印原文。另一次仅在实验请求禁用thinking，即生成并运行成功。

这三个都是独立探测，不混入主集；只足以证明接入差异值得处理，不能估计所有新模型调用的失败率。供应商当前[思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)说明默认开启及显式开关；产品尚无相应供应商能力设置，不能直接更换名称后宣称升级完成。

### 3.3 修复与创意共用额度

六条真实CLI `run` 路径结果：

| 输入/方式 | 实际结果 | 模型请求 |
| --- | --- | ---: |
| 普通未知文本“石头竞选星期八市长” | model_creative，竞选公告/票数/日历外当选 | 1 |
| 明确`--play`的影子/路灯隐喻 | model_creative，英文短诗 | 1 |
| 坏C默认模式 | 两次补丁均被拒绝，额度耗尽后print_input | 2 |
| 同一坏C直接`--play` | model_creative，外星猫/宇宙/星期八的小程序 | 1 |
| 正常中文任务“十只鸭子庆祝” | generated，不冒称creative_fallback | 1 |
| 合法C | native_ok，输出native preserved | 0 |

坏C是`int main(void) { return 外星猫(宇宙[0], 星期八); }`。默认路径的两次补丁删除整段原文，按现有规则拒绝后已无模型候选额度给创意。这里必须保留修复/创意的实际分配含义，不能仅因最终creative_fallback就说模型创作发生了。

### 7.3 实际作品变化与剩余问题

旧数学候选的6份原源码经新生产`build_in_temp(link_math=True)`和`run_creative_command`全部通过，未手工加参数或改源；这只是旧候选回归，不计新模型分母。新主集F02/F22/F28也都首轮构建通过，说明之前的链接障碍在真实新生成中没有再阻断。

“月亮正在摸鱼”的新作品用波纹与月亮组成小场景，结尾是：

```text
水面泛起两圈涟漪，鱼没摸到，
但月亮说：摸鱼也是一种发光。
```

“我的显卡想退休”的新作品写：

```text
显存里住过太多黄昏。
帧率像潮水，退了又退。
请准我，把光栅化交给晚霞。
最后一行日志：温度正常，梦已超频。
```

“纸飞机与宇宙”出现真实逐行轨迹与小诗；“风扇摇篮曲”把扇叶方向、音节和星点数量连成波形；十只鸭子的庆祝有10个角色及台词。相比通用英文说明/字节统计，题材和呈现的联系更强，但没有要求所有作品都变成复杂算法。

仍有明确缺陷：

- **F12非法UTF-8**：新模型把多字符常量`'☀'`存入char数组，GCC给multichar/overflow警告但默认构建成功。主集测量仍有乱码，不能声称提示彻底解决编码。生产run护栏对同一已有产物实测拒绝，stdout哈希与主集完全一致；原build报告明确validation.performed=false。只证明坏产物会被挡住，不代表该次作品已修复。
- **F02数学叙述错误**：程序能执行，却把角度/象限和口诀变化对应错，不能因为修好链接就称数学意图正确。
- **S12迷宫未抵达出口**，结尾却声称被括号包住；**S13电梯**实际星点递增，却宣称结尾变轻，且把换行打印成字面量；**S18**递增到20后又声称完成10→0。这些是机械护栏无法证明的语义问题，两位均扣分。
- **F24/F29**仍有字节统计包装，**S19**把全角空格按3个可见字符统计；新提示减少但没有消除模板和UTF-8计数误解。
- 严格`-std=c11`附加探针还发现M_PI等可移植性/编译警告，单列为诊断。产品当前默认GCC构建并运行成功，不把额外flag失败冒称默认产品编译失败。
