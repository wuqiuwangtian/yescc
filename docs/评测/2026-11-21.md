## 子 agent 新题盲评

被测提交 `5467c61` 对应的本地 wheel 安装到仓库外的新环境，平台 Linux/WSL。三个无开发历史的子 agent 独立出题；两道链接失败的 C、两道自由文本，输入在运行前固定。一次含越界读取的初稿在运行前排除，换成安全的未定义函数。每题普通 run 与 wild 各一次，关闭模型缓存，四题中各两题将 wild 放在 A/B。生成后两位子 agent 只收到题面和实际 stdout，独立评估忠实度、改编幅度和更想接着玩的版本。两人各参与一道题的设计；盲化针对档位，文件访问按协议约束，未做强隔离。

两人对哪份更忠实四题全部一致，其中三题是 wild。对“哪份改编更多”的判断，末站均选 A、收音机均选 A、影子均选 B、雨伞分别选 A 和 B。每个输入每档只采一次，模型有随机性。不能从四题推断真人偏好或总体胜率，也不能以末行、退出码都正确推定整部作品遵守题面。

八次真实请求均为 deepseek-flash，每件作品一次请求、退出 0、无本地模型缓存命中、输入字节不变，七个 model_creative 和一个 generated。每任务预留上限 $0.003，整轮 $0.024。已知 usage 为 4156 输入和 3672 输出 tokens，按前述峰时价合计 **$0.0056532**，未包含宿主 agent 的费用。没有为失败作品重新抽样。

另一个子 agent 独立做了四次离线验证，报告、源文件哈希与原始终端输出经主导者复核。正常 C 原生直通，双档均能机械修好全角分号，自由文本回显；均零模型尝试，解释报告区分了三种路径。首次输入 `yescc --offline run normal.c` 时得到误导性的多文件提示，使用帮助中给出的子命令顺序即可运行。[八件作品、题面、两份评分选择及离线记录](data/creative-blind-2026-11-21.json.gz)

## 模型如何理解限定范围

两个未继承开发历史的子 agent 分别设计一对新输入。典当行小票是自由文本，陶窑开窑是含未定义动作的 C。每对输入只替换范围词：限定整份作品，或只限定末行。运行前确定判定方法，先严格解码 UTF-8、统一 CRLF、去掉至多一个末尾换行。整份与目标逐字比较，末行题只比较最后一行；前面是否有非空文字另计，只有暗号也符合末行题。

以 5e9223b 为基线，在两个仓库外环境安装旧开发 wheel 和本轮 wheel，两个版本均为 Python 3.11.15、同一 WSL/GCC 和相同依赖。四输入 × default/wild × 两版本共 16 项，交错运行。另两项仅用新默认档复查既有失败题。每项一次 CLI 调用，无本地缓存，未重抽。完整输入、原输出、生成 C、版本标识、逐项格式检查和模型 usage 见[试用记录](data/output-scope-2026-11-21.json.gz)。

| 机械判定 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 整份只能打印指定短句 | 3/4 | 3/4 |
| 末行精确打印指定短句 | 4/4 | 4/4 |
| 末行题在暗号前另有内容（观察项） | 4/4 | 4/4 |

两版失守的都是 wild 的整张小票。新版在指定的“潮汐两讫”前后都写了旁白，甚至另起一行核对小票规矩。其余七项格式符合要求。陶窑的两档在只许一行时都输出“这只碗有点歪。”；只限末行时，两档都另有前文，wild 还写出了碗沿、釉色和开片纹路。这组采样没有显示新题通过率提升。

上轮水母默认档提了四个问题，这次考官只问一次，雨伞分三次作答并以“咕”收尾。影子题仍有错误：新版把站表演成四位乘客分别在某站下车、各自影子在下一站下车，最后一个影子留在水塔等天亮；没有演出题设中一名旅客离开后影子才独自抵达水塔的第五拍。每题只取一份新作品，无法据此断言稳定修复或估计人类偏好。
