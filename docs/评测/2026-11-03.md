# 2026-11-03 基线：M1 原生直通与包装开销

## 环境

- WSL2 / Arch Linux，x86_64
- Python 3.11.15（uv 虚拟环境）
- gcc 16.2.1
- Node.js v26.3.0

## 样本与方法

- 样本：`tests/fixtures/legal_cases.py`，Python / C / JavaScript 各 30 例，共 90 例。
- 判定：同一份源码分别交给原生工具链与 `fcomp run`，比较 stdout、stderr 与退出码；同时检查源码 sha256 未变、报告 `privacy.cloud_used` 为 false、attempts 全部为 `native`。
- 额外对照：30 个 C 样本的 `fcomp <file> -o out` 与 `gcc <file> -o out` 构建结果与运行输出一致。
- 包装开销：`bench/overhead.py --repeat 20`，进程墙钟减去报告内工具链耗时；含解释器启动。

## 结果

| 语言 | 次数 | 包装开销 P50 (ms) | 包装开销 P95 (ms) | 墙钟 P95 (ms) | 工具链 P95 (ms) |
| --- | --- | --- | --- | --- | --- |
| python | 20 | 34 | 36 | 57 | 22 |
| c | 20 | 36 | 39 | 64 | 26 |
| javascript | 20 | 39 | 42 | 66 | 27 |

- 本地 `pytest`：173 passed（单元 + e2e）。
- 结论：包装开销 P95 最大 42 ms，低于 G1 门槛 200 ms；合法样本行为一致、源码 0 修改、0 模型调用均满足。

## 双平台 CI 结果

GitHub Actions `windows-latest` 与 `ubuntu-latest` 均完成 e2e：

- Windows：`pytest -m e2e` 134 passed / 0 skipped（Python 3.11 与 3.14 各一轮），C 工具链由镜像自带的 GCC 提供，Node.js 由镜像提供。
- Linux：`pytest -m e2e` 134 passed / 0 skipped（Python 3.11 与 3.14 各一轮）。
- 另有 39 个单元测试在 `test` 任务中运行（两平台 × Python 3.11–3.14）。

## 未验证 / 限制

- Windows 结果来自 CI 虚拟机，未在真实 Windows 桌面手工复测；不同 MinGW 版本的诊断文本可能不同。
- 样本为短程序，覆盖函数、循环、文件读写、stdin、Unicode、参数等常见路径，不代表项目级兼容性。
- 包装开销只测了小文件冷启动路径，未测大型源码或并发场景。
- 慢速 CI runner 上的绝对耗时不代表用户机器。
