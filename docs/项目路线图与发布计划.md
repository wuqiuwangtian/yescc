## 1. 目标与完成定义

**总目标**：把现有「需求 + 调研」阶段文档，推进为在 GitHub 上以 MIT 协议公开发布、同步发布到 PyPI、Linux/Windows 原生可用、陌生人 5 分钟内可装好跑通的命令行 MVP（`v0.1.0`）。

**v0.1.0 的「完成」= 同时满足**：

1. `pipx install fcomp` 从 **PyPI 正式下载**，在 Linux 与 **原生 Windows（非 WSL）** 均可用；
2. 首批语言 **Python / C / JavaScript 单文件** 的原生直通行为与工具链一致（0 改写、0 模型调用）；
3. 常见小错误可修复且经真实工具链验证；自然语言可生成可运行短程序；
4. 无伪造成功：失败有明确状态与退出码，未验证结果单独标注；
5. MIT LICENSE 与社区文件齐备，CI 全绿，GitHub Release 与 PyPI 均发布成功。

**明确不做（v0.1.0 非目标）**：跨文件/项目级构建、VS Code 插件、macOS 官方支持、MSVC/`cl` 适配、运行时自动修复、内置本地模型、二进制免安装分发、GUI。

**与原始需求的关系**：「所有语言」「编辑器插件」「Linux+Windows」全部保留为长期目标；本版按已确认的分期执行，能力矩阵逐语言、逐能力如实声明，未覆盖语言给出诚实状态而非假装成功。

**核心承诺（全版本适用）**：合法代码不因本工具改变行为；内部诊断默认不直接抛给用户，但真实工具链始终是最终裁判；任何「成功」都必须有真实产物或真实执行作证。

### M1 原生直通与 CLI 骨架

**目标**：证明「合法代码零干扰」这条底线，并定死对外接口。

**交付物**

- [x] 命令行解析：`fcomp <file> [toolchain args...]`、`fcomp run <file> [-- args]`、`--lang`、`--strict`、`--explain`、`--json`、`--no-cache`；带值选项（`-o/-I/-L/-D` 等）成对透传
- [x] `LanguageAdapter` 协议 + 注册表；C 透传 `-o/-I/-L/-O/-std` 等，Python 用 `py_compile`，JS 用 `node --check`（Node 26 实测可解析 ESM）
- [x] 直通语义：合法输入不注入参数、不改源码、不调模型；`--strict` 直接透传原诊断
- [x] 退出码协议（§6.5）、产物管理、报告 v1 落盘 `.fcomp/<stem>/`
- [x] 合法样本集：每语言 30 个（共 90），覆盖函数、循环、文件读写、stdin、Unicode、含空格路径、参数；与原生工具链对照
- [x] 冷启动开销基准：20 次采样/语言，分列工具链耗时与包装开销

**Gate G1**：Linux + Windows 合法样本 100% 行为一致；源码 0 修改；JSON 报告中模型调用数为 0；包装开销 P95 ≤200 ms。——**已完成**：双平台 e2e 各 134 通过（90 例合法程序 + 30 例 C 构建对照 + 14 项 CLI 契约）；本地包装开销 P95：Python 36 ms / C 39 ms / JS 42 ms，证据见 `docs/评测/2026-11-03.md`。

**不通过处理**：若开销超限，先测启动路径（延迟 import、减少依赖），不得以牺牲一致性换速度。

### M2 诊断与规则修复

**目标**：在**不调用模型**的前提下，处理最常见的小错误，并守住「不误改合法代码」。

**交付物**

- [ ] 诊断解析：GCC `-fdiagnostics-format=json`；Python `compile()` 异常（行列+消息）；Node stderr 结构解析；统一 `Diagnostic`，保留原始文本
- [ ] 词法护栏：Python 用 `tokenize`；C/JS 用约 150 行状态机，只在字符串/注释之外替换
- [ ] 规则集：全角标点→ASCII、缺失闭括号/引号、常见笔误；每条规则产出候选，**必须交真实工具链验证**；多候选按改动范围排序，不宣称意图正确
- [ ] 损坏样本集：每语言 ≥30 个（缺括号、缺引号、全角、缩进、标识符笔误、多错组合），由正确程序 + 独立测试生成，损坏前源码不喂给模型
- [ ] 「多条合法补法」时记录歧义，不强行判唯一答案

**Gate G2**：规则可解子集意图正确率 ≥90%；合法样本零回归；失败样本 0 假成功。

**不通过处理**：优先缩窄规则触发条件而不是放宽验收；宁可少修，不可误改。

### M3 模型修复与自然语言生成

**目标**：接入模型，把「修复」和「自然语言生成」做成受预算约束、可验证的受控路径。

**交付物**

- [ ] 模型层：provider 抽象 + 四类适配器（OpenAI 兼容、Anthropic、Gemini、Azure OpenAI），`httpx` 实现；本地模型走 OpenAI 兼容端点；`base_url` / `model` / `api_key` 可配；无 key 时优雅降级为「仅规则」并提示，不自动联网（见 [ADR-0008](adr/0008-model-provider-coverage.md)）
- [ ] 补丁协议：模型只返回 **unified diff + assumptions**；自研严格补丁器，上下文不匹配即拒绝；不允许整文件改写；验证失败可再试 1 轮（总 ≤2 轮）
- [ ] 上下文策略：单文件全文（上限 24 KB）+ 诊断 + 用户意图；超限先截断无关区段并在报告标注
- [ ] 预算：2 次调用 / 60 s 模型墙钟 / 180 s 任务墙钟 / token 与费用上限，触顶即停
- [ ] 缓存：键 = sha256(源码 + 诊断签名 + 适配器版本 + 工具链版本 + 模型 + prompt 版本 + 参数)，本地 TTL 7 天，不跨用户
- [ ] 自然语言：`fcomp idea.txt --lang python [--run]`；先确定输入输出约定与边界假设，再生成、构建；未验证时状态为 `generated_built`，不写成功
- [ ] 隐私：首次云端调用显式告知上传范围；`FCOMP_OFFLINE=1` 禁网；日志脱敏

**Gate G3**：用假模型服务器保证 CI 确定性；真实模型评测记录 pass@1 与每正确结果成本，据此定首版门槛（建议 pass@1 ≥50%、规则类 ≥70%，以实测为准）；假成功率 0。

**不通过处理**：若真实模型效果不足以支撑「AI 修复」定位，缩小 NL 生成承诺、保留修复能力，并重新评审发布定位（你的决策点），不用夸大文案替代能力。

### M4 隔离、安全、跨平台加固

**目标**：让「执行 AI 生成的代码」这件事有明确、可复述的安全边界。

**交付物**

- [ ] 隔离执行器：临时目录副本、环境变量白名单（剔除密钥）、超时、POSIX 资源限额；Linux 尝试 `unshare -n` 断网，失败则报告 `network_isolated=false`；Windows 无断网能力并如实文档化

**Gate G4**：全部对抗用例行为符合声明；报告字段与实际一致；无密钥泄漏。

**不通过处理**：缩小声明而不是假装隔离；Windows 限制必须出现在 README 已知限制中。

## 6. 技术方案

### 6.1 技术栈

Python ≥3.11；`uv`（锁版本 + 环境）；`hatchling`（打包）；运行时依赖仅 `httpx` + `platformdirs`；开发依赖 `pytest`、`pytest-cov`、`ruff`、`mypy`、`build`。不引入 `typer/rich`（控制启动开销与依赖面）。`tomllib` 读配置。

### 6.2 目录结构

```text
pyproject.toml  LICENSE  README.md  CHANGELOG.md
CONTRIBUTING.md CODE_OF_CONDUCT.md SECURITY.md
src/fcomp/{cli,pipeline,config,report,errors,cache,util}.py
src/fcomp/adapters/{base,registry,python,c,javascript}.py
src/fcomp/diagnostics/{python,c,javascript}.py
src/fcomp/fix/{rules/*,model/*,budget.py}
src/fcomp/sandbox/{runner,limits}.py
tests/{unit,integration,e2e,fixtures}/
bench/{legal,broken,nl,harness.py}   # 不进 wheel
docs/{初版需求报告,技术参考与验证计划,GitHub开源项目调研,项目路线图与发布计划}.md
docs/{adr,评测}/
.github/{workflows,ISSUE_TEMPLATE}/
```

### 6.3 处理流水线

```text
输入 → 语言判定（扩展名 / --lang / 内容启发）
  ├─ 源码且原生成功 → 直接产物，结束（0 模型调用）
  ├─ 源码且失败 → 诊断分类 → 规则候选 → 验证
  │        └─ 仍失败且有预算 → 模型 diff → 严格应用 → 验证 → ≤2 轮
  └─ 自然语言 → 约定输入输出 → 生成 → 构建 →（可选）运行
统一产出：产物 / 补丁 / 报告 / 退出码；源文件永不覆盖
```

### 6.4 适配器协议与能力矩阵

协议：`detect / build_command / run_command / parse_diagnostics / capabilities / toolchain_version`。

v0.1.0 矩阵：三语言均支持「原生构建、规则修复、模型修复、自然语言生成、运行」；「跨文件、项目构建、MSVC」明确为否。平台：Linux x86_64（Arch 基线）+ Windows x64（MinGW-w64 GCC，CI 原生验证）；macOS 不承诺。

### 6.5 CLI 契约与退出码

| 码 | 含义 |
| --- | --- |
| 0 | 成功（构建成功；`run` 模式下程序自身退出 0） |
| 100 | 用法错误 |
| 101 | 不支持的语言/输入 |
| 102 | 构建失败或无法修复 |
| 103 | 预算/超时/取消 |
| 104 | 内部错误 |
| 其他 | `run` 模式下 = 用户程序退出码 |

`--json` 在构建模式下输出结构化结果到 stdout；`run` 模式下程序拥有 stdout，`--json` 按用法错误拒绝（100），报告始终落盘。人类摘要走 stderr；用户程序的 stdout/stderr 原样保留，不混入产品提示。

### 6.6 报告 schema v1（`report.json`，只增不改）

```text
schema_version, tool{version}, invocation{argv,mode,lang},
input{path,sha256,bytes,encoding},
toolchain{adapter,command,version},
diagnostics[],
attempts[{kind,round,patch,exit,duration_ms,tokens,cost}],
result{status:native_ok|fixed_verified|fixed_unverified|generated_built|failed|budget_exceeded,
       artifacts[],tests[],assumptions[]},
timings{total_ms,model_ms},
privacy{cloud_used,uploaded_bytes},
limits{network_isolated,...}
```

### 6.7 配置与环境变量

`~/.config/fcomp/config.toml`（Windows 走 `%APPDATA%`）：`model.base_url/name/api_key_env/max_calls/max_input_bytes/timeout_s`、`run.timeout_s`、`sandbox.*`、`cache.enabled`。环境变量 `FCOMP_*` 覆盖；密钥只从环境变量读取，绝不写入配置与报告。

### 6.8 产物与源文件保护

`.fcomp/<stem>/{patched.<ext>, patch.diff, report.json, build/}`；`--explain` 读最近报告，0 模型调用；`.fcomp/` 默认 gitignore；构建失败不得留下看似属于本次成功的陈旧可执行文件。

### 6.9 模型层与预算

- 提供方：v0.1.0 覆盖 OpenAI 兼容端点（OpenAI、DeepSeek、Qwen、Moonshot、vLLM、Ollama、LM Studio）+ Anthropic Messages + Google Gemini + Azure OpenAI，详见 [ADR-0008](adr/0008-model-provider-coverage.md)。
- 选择方式：`FCOMP_MODEL_PROVIDER` / `FCOMP_MODEL_BASE_URL` / `FCOMP_MODEL_NAME` / `FCOMP_MODEL_API_KEY`（Azure 另需 `FCOMP_MODEL_API_VERSION`）；配置文件只存非敏感字段，密钥只从环境变量读取。
- 调用上限：2 轮；单轮输出上限；输入上限 24 KB；任务总墙钟 180 s。
- 触顶行为：立即停止、保留部分结果、状态置 `budget_exceeded`、退出码 103。
- 费用记录：按实际 token × 单价写入报告；单价由配置提供，不内置价格表。
- 缓存：本地、按内容寻址、TTL 7 天；`--no-cache` 可绕过；不跨用户共享。

### 6.10 隔离与安全

- 验证在临时目录副本中执行，环境变量白名单，剔除 `FCOMP_*` 与常见密钥变量。
- POSIX：`setrlimit` 限制 CPU/内存/文件大小；`unshare -n` 尝试断网，失败如实记录。
- Windows：仅超时与进程树清理，不断网，README 明示。
- 用户显式 `fcomp run` 在真实 cwd 执行（原生语义），只加超时。
- 中断：SIGINT/取消后清理临时目录，不再发起模型调用。

## 7. 质量与验收

### 7.1 测试分层与 CI

单元（词法护栏、补丁器、诊断解析、预算）→ 集成（假编译器 / 假模型服务器，双平台）→ e2e（真实 gcc/python/node，Linux+Windows）→ 打包冒烟（wheel 安装后 `fcomp --version`）。CI 不调用真实模型（成本与不确定性），真实评测走手动任务并留档 `docs/评测/`。核心模块行覆盖 ≥80%，适配器 ≥90%（目标值，G5 复核）。

### 7.2 指标口径（与需求报告 §10 对齐）

原生兼容率、构建成功率、意图正确率、pass@1、不必要修改率、假成功率、P50/P95 延迟（分工具链与包装开销）、每任务 token/费用、单正确结果成本、失败收敛准确率。

### 7.3 基准数据集

| 类别 | 规模（起点） | 标注 | 判定 |
| --- | --- | --- | --- |
| 合法程序 | 每语言 ≥30 | 源码 + 固定环境 + 输入 | 与原工具链行为一致、0 修改、0 模型调用 |
| 受控损坏 | 每语言 ≥30 | 正确程序 + 损坏版本 + 独立测试 | 意图正确率；不要求逐字还原 |
| 自然语言 | 30–50 个中文任务 | 规格 + 隐藏测试 + 关键假设 | pass@1；两轮后成功率单列 |

合成样本结果不外推到真实项目；模型自测只作补充，不作唯一验收依据。

### 7.4 发布验收清单（G5/G6 共用）

- 第三方依赖许可审计入发布清单；只引入与 MIT 兼容的依赖。

### 8.2 协作规范

### 8.3 社区文件

README、CONTRIBUTING、CODE_OF_CONDUCT、SECURITY（漏洞私下报告）、CHANGELOG、issue/PR 模板、公开 Roadmap。

### 8.4 发布流程

版本号与 CHANGELOG 定稿 → 构建 sdist/wheel → GitHub Release → PyPI（Trusted Publishing 优先，token 兜底）→ 干净环境安装验证 → 公告。

### 8.5 发布后

issue 分诊、0.1.x 补丁、按反馈重排 0.2（跨文件 / 更多语言 / VS Code 插件）。路线图更新只改本文与公开 Roadmap 一处。

## 9. 风险登记册

| 风险 | 概率/影响 | 缓解 |
| --- | --- | --- |
| Windows 工具链发现与参数差异 | 高/高 | 锁定 MSYS2/MinGW-w64，CI 原生验证，能力矩阵明示 MSVC 不支持 |
| 模型修复质量不足 | 高/高 | 规则优先、严格 diff、2 轮上限、真实评测定档；不过 Gate 则缩 NL 能力并重新评审定位 |
| 成本/延迟超预算 | 中/高 | 预算硬上限、缓存、上下文限制、本地模型可替换 |
| 「不报错」被误解为「必定成功」 | 中/高 | 友好终止定义 + 状态字段 + 文档 + 退出码 |
| 执行 AI 生成代码的安全边界 | 高/高 | 临时目录、超时、环境白名单、Linux 断网、Windows 限制如实声明 |
| 范围蔓延（所有语言/插件） | 高/中 | 非目标清单 + 能力矩阵 + 路线图分期 |
| 投入不稳定导致 Gate 拖延 | 中/高 | 纯 Gate 推进；优先砍非目标，不砍「原生一致/无假成功」 |
| PyPI 首次发布失败或凭据缺失 | 中/中 | 名称已验证可用；M0 即做 TestPyPI 空跑演练；保留 Trusted Publishing 兜底 |
| 依赖许可/供应链 | 低/中 | 依赖最小化、许可审计、锁定版本 |
| 命名/商标冲突 | 低/中 | 发布前检索 `fcomp` 与产品名 |
