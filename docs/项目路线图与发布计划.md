## 1. 目标与完成定义

**一句话**：YesCC 是一个「永不扫兴」的 AI 编译器——正确代码原样编译；错误代码尽力修复；连自然语言或胡言乱语，也尽量变成一个能运行的程序。

**三条承诺**：

1. **正确代码绝不打扰**：原生工具链成功即结束，不调用模型、不修改源码、不注入参数。
2. **错误代码尽力挽救**：规则 → 便宜/本地模型 → 强模型，每层都必须交真实工具链验证。
3. **无意义输入也给出创造性解释**：确定性兜底、文化梗、模型创意解释；结果状态单独标注，绝不冒充原程序。

**v0.1.0 的「完成」= 同时满足**：

1. `pipx install yescc` 从 PyPI 安装，以及免安装二进制，在 Linux 与原生 Windows 均可用；
2. C 语言完成「原生直通 → 规则修复 → 模型修复 → 自然语言生成」完整闭环，且全部经真实编译；
3. Python / JavaScript 的原生直通行为与各自工具链一致（AI 修复与生成留到 0.2）；
4. 所有**输入类**失败默认进入创意兜底，状态为 `creative_fallback`，报告可追溯；环境类失败如实报错；
5. 无伪造成功：状态、退出码与报告一致，`--strict` 可关闭 AI 与兜底；
6. MIT LICENSE、社区文件、CI 全绿，GitHub Release 与 PyPI 发布成功。

**明确不做（v0.1.0 非目标）**：Python/JS 的 AI 修复与生成、跨文件/项目级构建、VS Code 插件、macOS 官方支持、MSVC、交叉编译、GUI、内置 Zig 工具链、Rust 重写。

**长期目标（不因本期缩小而删除）**：所有语言、编辑器插件、跨平台产物、社区梗库与在线 Demo。

## 6. 技术方案

### 6.1 技术栈

Python ≥3.11；`uv`；`hatchling`；运行时依赖：`httpx`、`platformdirs`、`tree-sitter`、`tree-sitter-c`；开发依赖：`pytest`、`pytest-cov`、`ruff`、`mypy`、`build`、`pyinstaller`。不引入 `typer/rich`。

### 6.2 目录结构（改名后）

```text
pyproject.toml  LICENSE  README.md  CHANGELOG.md
CONTRIBUTING.md CODE_OF_CONDUCT.md SECURITY.md
src/yescc/{cli,pipeline,config,report,errors,cache,util}.py
src/yescc/adapters/{base,registry,python,c,javascript}.py
src/yescc/diagnostics/{base,c,python,javascript}.py
src/yescc/fix/{rules/*,model/*,budget.py}
src/yescc/fallback/{deterministic,easter_eggs,creative}.py
src/yescc/model/{provider,tiers,openai_compat,litellm}.py
src/yescc/sandbox/{runner,limits}.py
tests/{unit,integration,e2e,fixtures}/
bench/{legal,broken,complex,nl,fun,harness.py}
docs/{初版需求报告,技术参考与验证计划,GitHub开源项目调研,项目路线图与发布计划}.md
docs/{adr,评测}/
.github/{workflows,ISSUE_TEMPLATE}/
```

### 6.3 分级流水线（L0–L4）

```text
输入
 ├─ L0 原生编译：成功 → native_ok，结束（0 模型调用）
 ├─ L1 确定性修复：候选补丁 → 真实编译 → 成功则 repaired
 ├─ L2 便宜/本地模型：最小补丁 → 真实编译 → 成功则 repaired
 ├─ L3 强模型：复杂修复或 NL→C → 真实编译 → repaired / generated
 └─ L4 创意兜底：梗规则 → 模型创意 → 确定性打印输入 → creative_fallback
环境类失败（缺工具链/依赖/权限/磁盘）→ failed，不进入 L4
```

### 6.4 结果状态与退出码

| 状态 | 含义 | 退出码 |
| --- | --- | --- |
| `native_ok` | 原生成功，源码未改 | 0 |
| `repaired` | 规则/模型修复后真实编译通过 | 0 |
| `generated` | NL/伪代码生成后真实编译通过 | 0 |
| `creative_fallback` | 生成了可运行但非意图等价的程序 | 0（stderr 强提示） |
| `failed` | 未产出（环境问题或兜底也失败） | 102/103/104 |

保留码：100 用法、101 不支持、102 构建失败、103 预算/超时/取消、104 内部错误。`--strict` 关闭 AI 与兜底，失败时返回 102 并显示原始诊断。

### 6.5 CLI 契约

```text
yescc <file> [工具链参数...]        构建（默认只编译，不运行）
yescc run <file> [-- 程序参数...]    构建后运行
yescc <file> --explain              查看最近报告
yescc <file> --emit-source          输出生成/修复后的源码
yescc <file> --trace                输出每层尝试与模型调用摘要
```

选项：`--lang python|c|javascript`、`--strict`、`--json`（仅构建模式）、`--offline`、`--budget`、`--max-rounds`、`--model`、`--provider`、`--play`（强制娱乐解释）、`--no-fallback`、`--unsafe-run`。TTY 下构建成功打印一行状态；管道下静默。程序 stdout/stderr 原样保留。

### 6.6 报告 schema v1（只增不改）

新增字段：

```text
result{status, artifact, program_exit, fallback{used,kind,reason}},
model{provider,tier,name,calls,prompt_tokens,completion_tokens,cost_usd},
fallback{trigger, rules[], deterministic, assumptions[]},
limits{sandboxed,network_isolated,timeout_s}
```

原有字段保持：`schema_version, tool, invocation, input, toolchain, diagnostics, attempts, timings, privacy`。

### 6.7 配置与环境变量

`~/.config/yescc/config.toml`（Windows `%APPDATA%`）：`model.l2.*`、`model.l3.*`、`budget.*`、`run.timeout_s`、`sandbox.*`、`cache.enabled`。环境变量 `YESCC_*` 覆盖；密钥只从环境变量读取。兼容读取旧的 `FCOMP_*` 一个版本，随后移除。

### 6.8 模型分级与供应商

- L2：Ollama / LM Studio / 小模型（本地优先），处理近正确补丁、分类、定位。
- L3：DeepSeek / OpenAI / 其他强模型，处理复杂修复与 NL 生成。
- 统一走 OpenAI 兼容协议；Anthropic/Gemini/Azure 通过各自兼容端点或可选 LiteLLM 网关接入，不各写原生协议。
- 无可用 provider 时：L0/L1 照常工作，L2/L3 跳过，L4 走确定性兜底。

### 6.9 沙箱与源文件保护

- 源文件永不覆盖；产物、补丁、报告写入 `.yescc/`（改名后）。
- 原生未修改代码的 `run` 用真实 cwd；AI 修复/生成/兜底产物默认沙箱运行。
- 报告中的 `limits` 与实际能力一致，不宣称强隔离。

## 9. 风险登记册

| 风险 | 概率/影响 | 缓解 |
| --- | --- | --- |
| 源码兜底被误当成修复成功 | 高/高 | 状态单列、stderr 强提示、`--strict` 关闭、报告保留原始诊断 |
| C 生成质量不足 | 高/高 | 分级模型、严格验证、兜底、真实评测定档 |
| Python 独立二进制体积/杀软误报 | 中/中 | PyInstaller onefile、干净机验证、文档说明；必要时评估 Nuitka |
| Tree-sitter 接入复杂 | 中/中 | 先只做 C；语法树只用于定位，修复仍走规则 |
| Windows 沙箱能力有限 | 高/高 | 仅超时与进程树清理，README 明示；不宣称强隔离 |
| 模型成本/限流 | 中/中 | 单任务预算、2 轮上限、缓存、本地模型 |
| 改名带来的链接/包名混乱 | 低/低 | 一次性机械改名；旧域名重定向；TestPyPI 同步 |
| 范围蔓延（Python/JS AI、插件、跨平台） | 高/中 | 非目标清单 + Gate |
| 娱乐化压过真实性 | 中/高 | 状态机与发布清单；整活覆盖率不替代意图正确率 |
