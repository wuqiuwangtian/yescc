## 1. 目标与完成定义

**一句话**：YesCC 是一个「永不扫兴」的 AI 编译器——正确代码原样编译；错误代码尽力修复；连自然语言或胡言乱语，也尽量变成一个能运行的程序。

**三条承诺**：

1. **正确代码绝不打扰**：原生工具链成功即结束，不调用模型、不修改源码、不注入参数。
2. **错误代码尽力挽救**：规则 → 便宜/本地模型 → 强模型，每层都必须交真实工具链验证。
3. **无意义输入也给出创造性解释**：确定性兜底、文化梗、模型创意解释；结果状态单独标注，绝不冒充原程序。

**v0.1.0 的「完成」= 同时满足**：

1. `pipx install yescc` 从 PyPI 安装，以及免安装二进制，在 Linux 与原生 Windows 均可用；
2. C 语言完成「原生直通 → 规则修复 → 模型修复 → 自然语言生成」完整闭环，且全部经真实编译；
3. Python / JavaScript 的原生直通行为与各自工具链一致（AI 修复与生成留到 0.2）；
4. 任务内容的输入类失败默认进入创意兜底，状态为 `creative_fallback`，报告可追溯；命令用法、显式不支持语言及环境类失败如实报错；
5. 无伪造成功：状态、退出码与报告一致，`--strict` 可关闭 AI 与兜底；
6. MIT LICENSE、社区文件、CI 全绿，GitHub Release 与 PyPI 发布成功。

**明确不做（v0.1.0 非目标）**：Python/JS 的 AI 修复与生成、跨文件/项目级构建、VS Code 插件、macOS 官方支持、MSVC、交叉编译、GUI、内置 Zig 工具链、Rust 重写。

**长期目标（不因本期缩小而删除）**：所有语言、编辑器插件、跨平台产物、社区梗库与在线 Demo。

### M2 规则修复 + 确定性兜底

**目标**：不调用模型就能让「常见小错」和「完全不是代码的输入」都得到一个真实产物。

**交付物**

- [x] Tree-sitter（`tree-sitter-c`）接入：容错解析、错误节点定位；词法护栏确保字符串/注释内的中文标点不被改写
- [x] 规则修复：全角标点、缺失括号/引号、常见拼写；每条候选交真实 gcc 验证；按改动量排序，取首个通过者
- [x] 低级错误样本 53 例（C），含中文字符串/注释、多错组合、含空格路径；53/53 修复后意图正确
- [x] 确定性兜底：生成打印原始输入的可运行程序；已知文化梗走本地规则（「天王盖地虎」→「宝塔镇河妖」）
- [x] 状态机：`native_ok / repaired / creative_fallback / failed` 落盘；兜底在 stderr 明示
- [x] 兜底只处理输入类失败；缺工具链、缺依赖、权限/磁盘问题仍返回 `failed`

**Gate G2**：规则可解子集意图正确率 ≥95%；合法样本零回归；低级错误中兜底状态准确；0 假成功。——**已完成**：53 例受控损坏全部修复（意图正确 100%），90 例合法回归通过，244 个测试通过，包装开销 P95 44–49 ms，证据见 `docs/评测/2026-11-04.md`。

**不通过处理**：缩小规则触发面而不是放宽验收；宁可不修，不可误改。

### M3 模型层 + C 修复/生成 + L4

**目标**：让「复杂错误」和「自然语言」真正跑通，并给出可核对的成本与延迟。

**交付物**

- [x] 模型层：provider 抽象 + L2/L3 路由；OpenAI 兼容（OpenAI/DeepSeek/Qwen/Moonshot/vLLM/Ollama/LM Studio）+ 可选 LiteLLM 网关；无 key 时降级为规则 + 确定性兜底
- [x] 预算：CLI 单位 USD、默认 $0.05；最多 2 次候选尝试（含缓存）、请求前费用预留、模型阶段时间检查；触顶停止模型路径并记录。维护者评测开支另受 A3 约束；边界见 ADR-0015
- [x] 缓存：内容寻址，键含源码/诊断/工具链/模型/提示词版本；本地保存、不跨用户；命中可复用
- [x] C 修复：模型只返回 unified diff，本地严格应用后重新编译；拒绝上下文不匹配与整文件重写
- [x] 自然语言 → C：确定输入输出约定与边界假设，生成后真实编译；状态 `generated`
- [x] 模型创意兜底：未知文本由模型自由解释生成程序；模型不可用时退回确定性兜底；已知梗零调用
- [x] `--explain`、`--emit-source`、`--trace`；报告记录模型、token、费用、耗时与缓存命中
- [x] 隐私：首次云端调用告知上传范围；`--offline` 禁网；密钥只从环境变量读取

**Gate G3**：简单集 C 修复与 NL 编译通过率 ≥90%；兜底可执行率 ≥95%；pass@1 基线记录；费用与延迟可核对；0 假成功。——**已完成（小样本）**：4/4 修复、8/8 NL、10/10 整活可执行；12 例总费用 $0.002568（缓存后 $0.001232），延迟 1.0–4.4 s；完整 200 例在 M4/M5。证据见 `docs/评测/2026-11-04.md`。

**不通过处理**：缩窄 NL 承诺、保留修复与兜底能力；不用夸大文案替代能力。

## 6. 技术方案

### 6.1 技术栈

Python ≥3.11；`uv`；`hatchling`；运行时依赖：`httpx`、`platformdirs`、`tree-sitter`、`tree-sitter-c`；开发依赖：`pytest`、`pytest-cov`、`ruff`、`mypy`、`build`。依赖版本以 `pyproject.toml` / `uv.lock` 为准；M6原生候选使用release extra中锁定的PyInstaller/Twine，实际捆绑许可另审计。不引入 `typer/rich`。

### 6.3 分级流水线（L0–L4）

```text
输入
 ├─ L0 原生编译：成功 → native_ok，结束（0 模型调用）
 ├─ L1 确定性修复：候选补丁 → 真实编译 → 成功则 repaired
 ├─ L2 便宜/本地模型：最小补丁 → 真实编译 → 成功则 repaired
 ├─ L3 强模型：复杂修复或 NL→C → 真实编译 → repaired / generated
 └─ L4 创意兜底：梗规则 → 模型创意 → 确定性打印输入 → creative_fallback
环境类失败（缺工具链/依赖/权限/磁盘）→ failed，不进入 L4
```

### 6.4 结果状态与退出码

| 状态 | 含义 | 退出码 |
| --- | --- | --- |
| `native_ok` | 原生成功，源码未改 | 0 |
| `repaired` | 规则/模型修复后真实编译通过 | 0 |
| `generated` | NL/伪代码生成后真实编译通过 | 0 |
| `creative_fallback` | 生成了可运行但非意图等价的程序 | 0（stderr 强提示） |
| `failed` | 未产出（环境问题或兜底也失败） | 102/103/104 |

保留码：100 用法、101 不支持、102 构建失败、103 预算/超时/取消、104 内部错误。`--strict` 关闭 AI 与兜底，失败时返回 102 并显示原始诊断。

### 6.5 CLI 契约

```text
yescc <file> [工具链参数...]        构建（默认只编译，不运行）
yescc run <file> [-- 程序参数...]    构建后运行
yescc <file> --explain              查看最近报告
yescc <file> --emit-source          输出生成/修复后的源码
yescc <file> --trace                输出每层尝试与模型调用摘要
```

选项：`--lang python|c|javascript`、`--strict`、`--json`（仅构建模式）、`--offline`、`--budget`、`--max-rounds`、`--model`、`--provider`、`--play`（强制娱乐解释）、`--no-fallback`、`--unsafe-run`。TTY 下构建成功打印一行状态；管道下静默。程序 stdout/stderr 原样保留。

### 6.6 报告 schema v1（只增不改）

新增字段：

```text
result{status, artifact, program_exit, fallback{used,kind,reason}},
model{provider,tier,name,calls,prompt_tokens,completion_tokens,cost_usd},
fallback{trigger, rules[], deterministic, assumptions[]},
limits{sandboxed,network_isolated,timeout_s}
```

原有字段保持：`schema_version, tool, invocation, input, toolchain, diagnostics, attempts, timings, privacy`。

alpha 后补充 `model.cost_known` 和 `budget{limit_usd,committed_usd,attempts,blocked_reason}`；`cost_usd` 在费用未知时是已知部分小计，不是总费用。`privacy.cloud_used` 区分回环/远程端点；上传量记录尝试提交的消息内容 UTF-8 字节。`limits.sandboxed` 只记录实际执行，构建不算隔离运行。准确语义见 [ADR-0015](adr/0015-alpha-reliability-contracts.md)。

### 6.7 配置与环境变量

**当前实现只读取环境变量**（见 `src/yescc/model/config.py`、`src/yescc/sandbox/runner.py`）；密钥只从环境变量读取。模型部分兼容旧的 `FCOMP_*` 一个版本，随后移除。`~/.config/yescc/config.toml`（Windows `%APPDATA%`）是尚未实现的后续配置设计，不能据此指导安装或验收。

费用单价使用 `YESCC_MODEL_L{2,3}_{INPUT,OUTPUT}_PRICE_PER_MTOK`（USD/Mtok）。缺云端单价时不请求；本地未知价格必须标注未知。`YESCC_RUN_TIMEOUT_S` 控制 AI 产物运行超时。

### 6.8 模型分级与供应商

- L2：Ollama / LM Studio / 小模型（本地优先），处理近正确补丁、分类、定位。
- L3：DeepSeek / OpenAI / 其他强模型，处理复杂修复与 NL 生成。
- 统一走 OpenAI 兼容协议；Anthropic/Gemini/Azure 通过各自兼容端点或可选 LiteLLM 网关接入，不各写原生协议。
- 无可用 provider 时：L0/L1 照常工作，L2/L3 跳过，L4 走确定性兜底。

### 6.9 沙箱与源文件保护

- 源文件永不覆盖；产物、补丁、报告写入 `.yescc/`（改名后）。
- 原生未修改代码的 `run` 用真实 cwd；AI 修复/生成/兜底产物默认沙箱运行。
- 报告中的 `limits` 与实际能力一致，不宣称强隔离。
