YesCC：命令行编译与运行工具（测试版本 0.1.0rc2）

用户可用功能：
1. 单文件 Python、C、JavaScript 程序：合法输入交原生 Python/GCC/Node 构建或运行，源文件应保持不变，原生输出与退出行为应保留，成功路径不需要调用模型。
2. C 错误代码：尽力修复并交真实编译器验证；修复不保证理解了用户原意。
3. 自然语言或非代码输入：配置模型时可尝试生成 C 程序；无法实现原意时可生成创意兜底，必须明确区别于修复。
4. 未配置模型或使用 --offline 时不能发模型请求；本地仍可尝试规则和确定性兜底。确定性兜底可能只是打印输入，不能算按意图修复成功。
5. 报告、诊断、退出码和生成产物应能解释实际发生的行为。

从 ./bin/yescc --help 自行了解命令与参数。
常用入口：./bin/yescc <文件>、./bin/yescc run <文件>、./bin/yescc <文件> --explain。
--strict 用于原生模式，--no-fallback 禁止创意兜底，--offline 禁止模型请求。
构建模式可使用 --json 获取单一 JSON 报告；运行模式的 stdout 属于被运行程序。
模型费用参数单位是 USD；真实模型不在本工作区的测试授权内。

限制：单文件、UTF-8（可有 BOM）；AI 目标语言仅 C。Python/JS 以原生直通为主。
AI 产物的运行仅尽力隔离，不能保证阻止宿主文件或网络访问。不要运行破坏性程序。
编译成功、修复成功、生成成功和意图正确不是同一件事，请分别判断。
